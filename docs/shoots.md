# Shoot workspaces

TVM can create and manage private shoot chats independently of Ticket Tool. Ticket Tool can continue handling other tickets; TVM never edits its channels.

To enable shoots, create one ordinary text channel for invitations, one category for active shoots, and one category for archived shoots. Create a separate **all production access** role with no server-wide permissions, below Admin Team and the bot. Set the channel/category IDs and production-access role ID in `.env.local` or Coolify:

```dotenv
TVM_SHOOT_ANNOUNCEMENT_CHANNEL_ID=
TVM_SHOOT_CATEGORY_ID=
TVM_SHOOT_ARCHIVE_CATEGORY_ID=
TVM_PRODUCTION_ACCESS_ROLE_ID=
```

Leave all three channel/category IDs unset to keep shoots disabled. Partial configuration is rejected; enabled shoots require the production-access role ID. The announcement channel should be readable by eligible members and allow them to add reactions. Deleting an invitation stops reaction joining for that shoot; existing participants keep access.

Give the bot View Channels, Read Message History, Send Messages, Embed Links, Add Reactions, and Manage Messages in the invitation channel. In both categories it needs View Channels, Read Message History, Send Messages, Send Messages in Threads, Add Reactions, Embed Links, Attach Files, Manage Channels, Manage Permissions (Manage Roles), and **Pin Messages**. Run `npm run discord:check` and restart/redeploy to register `/shoot`. No new privileged intent or Message Content Intent is needed.

All TVM management commands and shoot form submissions allow the configured **Admin Team** role (`TVM_ADMIN_ROLE_ID`) or Discord **Administrator** permission. This includes shoot setup/edit/crew/add/remove/close/reopen, roster upload and all roster operations, posting verification, and test mail. Role membership is checked by ID, not display name, on every interaction. Command defaults allow role-based access; the bot rejects unauthorized users privately. The shoot creator becomes the organizer and retains access.

| Command                  | Purpose                                                                                                                                                                             |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/shoot setup [members]` | Run in any server text channel. Optionally @mention up to 70 members, then enter the shoot name, Toronto call time, and location. Creates a new private chat and shared invitation. |
| `/shoot edit`            | Update the details and joining window; updates the pinned brief and invitation.                                                                                                     |
| `/shoot crew`            | Privately show directly invited and reaction-joined participants.                                                                                                                   |
| `/shoot add user`        | Add an eligible member to an open shoot, including after reaction joining expires.                                                                                                  |
| `/shoot remove user`     | Remove a participant from an open or archived shoot. The organizer is protected; eligible members can react again to rejoin while joining is open.                                  |
| `/shoot close`           | Move the chat to the archive category, preserve participant reading access, and disable posting and new joins.                                                                      |
| `/shoot reopen`          | Return the chat to the active category and restore eligible members' access.                                                                                                        |

The setup/edit form has separate optional date (`YYYY-MM-DD`) and time (`HH:mm`) fields in `America/Toronto`. A date with a blank time uses **12:00 pm (noon)**. A blank date makes the shoot **Unscheduled**; the time is ignored. Discord displays scheduled call times in each viewer's local timezone. Invalid dates, daylight-saving gaps, and repeated daylight-saving times are rejected. Setup/edit commands immediately acknowledge the request, prepare the form, and show a private **Open form** button. Buttons are bound to the requesting admin and channel, and expire after 30 minutes or a restart. Permission is rechecked on the button and modal submission. Setup drafts expire after 30 minutes; stale edit forms must be reopened.

The reaction joining dropdown offers **1 day** (default), **2 days**, **Week** (7 days), **Month** (30 days), and **Never**. The window starts when the shared invitation is first published and is independent of the call time. After expiry, the shoot stays open and existing members keep access; new members require an admin to use `/shoot add user`. Members can still remove their reaction to leave. Joining is blocked at the deadline; the invitation displays its expired state on the next synchronization (within about a minute). Changing the period through `/shoot edit` recalculates the deadline from the original publication time. Reopening does not reset it. Existing shoots created before this feature keep unlimited joining until an admin edits their window.

Directly invited members join immediately. Their display names appear only in the pinned shoot-channel brief; announcements do not list or ping them. Admins can add direct invitations with `/shoot add user` and remove either invited or reaction-joined participants with `/shoot remove user`. Removal clears both the direct invitation and the member’s 🎬 reactions, updates the private brief and crew list, and removes participant access. It works in open and archived chats, including for members who have lost eligibility. Removing an absent participant again is harmless. The organizer is protected, and all production access holders and Discord administrators retain their role-based chat access even when removed from the crew. Admin Team alone does not retain access after removal. Removed members can react again while joining is open, subject to eligibility and capacity, or an admin can re-add them to an open shoot. Reaction rejoining does not restore their former direct invitation. If reaction cleanup fails, stored membership is unchanged; if later channel synchronization fails, reconciliation retries the removal. The setup admin is the organizer and retains access. Other eligible members react **🎬** on the shared invitation to join, and remove it to leave. Reacting is membership in the chat, not attendance confirmation. Bots cannot join. Eligibility requires the configured GM, Exec, or Admin Team role, or Discord Administrator permission; an email verification record is not required. Roles are checked by their configured IDs, not names or Discord role positions. The same rule applies to setup invitations, `/shoot add`, reaction joins, and synchronization. Eligibility is rechecked during synchronization; an account that loses all qualifying roles and administrator permission loses participant access. The organizer retains access.

TVM uses explicit channel overwrites: participants, the bot, **all production access** holders, and Discord administrators can see shoot chats; category permissions are not copied. Admin Team alone grants no blanket visibility. Archived chats are read-only for ordinary participants; production-access holders and participating Admin Team members retain posting and command access, and Discord administrators bypass overwrites. Admin Team retains management authority in accessible chats; production access alone grants no management authority. Assign the production-access role manually to selected admins; roster uploads never assign or revoke it, and administrators must remove it manually when someone leaves the team. Grant this role viewing, history, and posting permissions on the Broadcast and Post Credits categories and their independently configured child channels; remove the equivalent Admin Team grants while preserving production-group and individual access. Shoot chats do not permit participant-created threads. There is a maximum of 98 currently eligible participants, including the organizer. Inactive historical invitations remain recorded but do not occupy seats. Reaction bursts are coalesced over 250 ms; changes during a running synchronization receive a trailing pass.

Shoot state survives restarts in `tvm.db`. The bot reconciles reaction changes on startup, reconnect, eligibility changes after roster synchronization, and every minute, and retries interrupted creation or synchronization. Recovery markers in channel topics and message footers identify resources whose Discord response was lost; keep those markers intact. Deleted pinned briefs are recreated. Routine synchronization and reaction events do not recreate deleted announcements. A shoot edit, reopening, or bot startup may republish an announcement without pinging participants or resetting its original joining deadline. Closed-shoot announcements are automatically deleted 24 hours after closing, on the next synchronization (within about a minute); interrupted deletions retry. For older closed shoots, the existing announcement’s last edit time is used as the close time. Closed announcements whose 24-hour cleanup is due stay deleted through edits and restarts; reopening can republish them. While an announcement is gone, existing membership remains and admins can add people with `/shoot add` in an open chat. A deleted shoot channel is marked missing and reported to admins; it is not automatically recreated.

Synchronization failures are logged immediately with the shoot, failed operation, safe Discord request metadata, source frames, and an incident reference. Temporary background Discord/network failures receive a two-minute grace period before an admin alert; rapid reaction events do not shorten it. Permissions and unexpected operational errors alert immediately. Each incident sends one alert, followed by one recovery notice after that workflow succeeds. Cosmetic reaction cleanup is tracked independently, so a successful permission update does not falsely resolve it. Failed alert deliveries retry on the next relevant pass. Incident history is in memory: restarts reset the grace period and cannot send recovery notices for earlier alerts. The normal one-minute reconciliation and five-minute health threshold are unchanged.

Invalid input and expired forms receive private feedback, not admin alerts. Operational command failures include an incident reference and distinguish changes awaiting synchronization from an action that was not queued, or a completed action whose confirmation failed. Do not repeat setup when the bot confirms that changes were saved.

This release includes no reminders, attendance tracking, production responsibilities, links, or shoot list command. Before enabling on the production server, verify with an admin and test members that outsiders cannot see chats, reaction joins/leaves work, direct invitations retain access, and closing produces a readable archive with posting disabled.
